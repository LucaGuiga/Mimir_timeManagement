Mimir API Privacy Policy

Last updated: September 30, 2026

Mimir is a personal, self-hosted academic planner. This policy covers the Mimir API, the small web service that receives dashboard snapshots from the owner's local machine and serves the dashboard. It is run by the Mimir owner ("we") for their own use and for people they explicitly invite.

What the API receives and stores

The local Mimir installation pushes snapshots about once a minute. Each snapshot is stored as JSON in a SQLite file on the API server. Only the latest copy of each snapshot is kept; new pushes overwrite old ones. Snapshots contain:

  • Stress score for today and up to 90 days of history
  • Upcoming assignments (course name, title, type, due date, status, commit counts)
  • Today's schedule blocks
  • Recent GitHub commit details (course, file path, file size, commit message, time)
  • Recent Oura sleep and readiness data (scores, HRV, resting heart rate, sleep duration)
  • Active error messages and polling health for the iCal, GitHub and Oura integrations

Health data from Oura is sensitive. It is used only to compute the stress score and show it on the dashboard.

What the API does not store

The API does not hold your Canvas login, your GitHub or Oura tokens, your Anthropic key, or your Telegram credentials. Those stay in the local configuration file on the owner's machine. The API has no user accounts, no advertising, no analytics and no tracking cookies.

Access and authentication

Every data endpoint requires a shared bearer token. The dashboard bundle includes that token, so anyone who can load the dashboard page can read the data. The dashboard is meant to live on a private address and should not be shared publicly. Only the health endpoint (/health) and these two policy pages are open. The health endpoint returns a status and the age of the oldest snapshot, nothing else.

Logs

The web server and any reverse proxy in front of it may record standard request details such as IP address, time, path and status code, for troubleshooting and security. These are not used for profiling.

Sharing

We do not sell or share snapshot data. It is hosted on Amazon Web Services infrastructure, which processes it on our behalf. We may disclose data if the law requires it.

Separately, the local Mimir app (not the API) talks to services you configure: your Canvas iCal feed, GitHub, Oura, an SMTP email server, Telegram, and the Anthropic API for syllabus parsing. Syllabus text you choose to parse is sent to Anthropic. Each of those services has its own privacy policy.

Retention and deletion

Snapshots are replaced on every push and are not archived. Stopping the local app stops new data. To delete everything, remove the SQLite file on the API server (sqlite_path in api/config.yaml). To request deletion of data held for you, open an issue at github.com/LucaGuiga/Mimir_timeManagement.

Security

Use HTTPS in front of the API, keep the token secret, and rotate it if it leaks (change api_token on both ends and rebuild the dashboard). No system is perfectly secure, and we cannot promise otherwise.

Children

Mimir is not directed at children under 13 and does not knowingly collect their data.
